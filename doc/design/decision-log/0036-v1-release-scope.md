# 0036 v1.0 リリースのスコープ

- 状態: decided
- 作成日: 2026-06-12
- 最終更新日: 2026-06-22
- 関連: `progress.md`, `doc/design/architecture.md`

## 背景

3 ステップ作業(詳細仕様確定 / アーキテクチャ選定 / PoC 実装)が完了し、`progress.md` の「本実装」フェーズのスコープを確定する必要がある。PoC は happy path の機能充足性を実 workspace への E2E で確認したが、テストコードなし、`--reuse-cache` 未実装、リリース自動化未整備の状態である。

## 候補

- (a) v1.0 公開リリースまでを 1 つのプランとする(テスト整備 + CI + 機能完成 + リリース整備 + 利用者向けドキュメント)。
- (b) 品質基盤(テスト + CI + 機能完成)までとし、リリース整備は別プランに分ける。
- (c) (a) に加えて未決事項(差分取得と再実行、blocks の構造レンダリング等)も前倒しで含める。

## 検討内容

- 単一バイナリ配布(GitHub Releases)はプロジェクトの最重要基準(0032 / 0034)であり、「Releases から取得してすぐ使える」状態をゴールにすると到達点が明確になる。
- (b) はゴールが中間状態で止まり、リリース整備のための再プランニングが挟まる。
- (c) は Issue 数と期間が膨らむ。未決事項の多くは「需要が確認できたら再検討」型であり、v1.0 公開後にフィードバックを得てから判断する方が無駄がない。
- 2026-06-12 にユーザーへ選択肢を提示し、(a) を確認した。

## 決定

v1.0 リリースまでを本実装プランのスコープとする。含むもの:

- テスト整備: パッケージ別ユニットテストと、fake Slack server による統合テスト。PoC の E2E 未確認項目(サイズ超過置換、tombstone、429 待機など)は統合テストの fixture で網羅する。
- CI: GitHub Actions(gofmt / vet / build / test / 4 target クロスコンパイル)。
- `--reuse-cache` の実装(0030 の整合性検証)。
- コンテナ実行時 timezone 課題の解決(0028 関連の未決事項)。
- system メッセージの actor 表示(0027 関連の未決事項)。
- リリース整備: goreleaser、release workflow、version 埋め込み。
- 利用者向けドキュメント(README / LICENSE)、実 token 総合 E2E、v1.0.0 リリース実施。

post-v1 として明示的に残すもの(未決事項のまま据え置き):

- 差分取得と再実行、CI artifact 化、thread replies を含む全体取得量、workspace mismatch の guard option、rich text(`blocks`)の完全レンダリング、出力制御 option、user 解決の最適化、Windows 対応、Homebrew tap。

## 理由

- 「単一バイナリ配布を重視する」というプロダクト意図に対し、v1.0 公開が価値を確定させる最短の到達点のため。
- post-v1 項目は利用実績からの需要確認を再検討条件としており、v1.0 前に決め打ちする必要がないため。

## 影響

- `progress.md` に「v1.0 リリース実装プラン」のタスク表を追加し、各タスクを GitHub Issue として登録する(タスク消化の運用方式は 0037)。
- timezone / actor 表示 / リリース整備の各未決事項は、対応する v1 タスクの中で決定・解消する。
- 2026-06-22 に v1.0.0 を GitHub Releases で公開し、本実装プランは完了した。

## 後から見直す条件

- v1 タスクの消化中に大きな仕様欠陥や前提崩れが見つかり、スコープの組み替えが必要になった場合。
