# 0010 Attachment File Downloads

- 状態: decided
- 作成日: 2026-06-02
- 最終更新日: 2026-06-02
- 関連: `../output-format.md`

## 背景

Slack posts をローカル HTML として保存する場合、画像だけでなく PDF、テキスト、zip、動画などの添付ファイルも投稿文脈の一部になる。

画像以外の添付ファイルを保存対象に含めるか、また大きすぎる添付ファイルをどう扱うかを決める必要があった。

## 候補

- 画像だけを保存し、画像以外の添付ファイルは Slack 上の参照情報だけを表示する。
- 画像以外の添付ファイルも可能な限り保存する。
- 画像以外の添付ファイルも保存するが、サイズ上限を超えるものは download せず、HTML 上では置換メッセージを表示する。

## 検討内容

画像以外の添付ファイルを保存しない方式は実装が単純だが、Slack 投稿の archive としては情報が欠落しやすい。

画像以外も無制限に保存する方式は archive としては完全性が高いが、巨大ファイルによる実行時間、出力サイズ、CI artifact サイズ、ローカル disk 使用量の問題が起きやすい。

サイズ上限を設ける方式なら、投稿文脈を可能な限り保存しつつ、予期しない巨大 download を避けられる。上限超過時は単に黙って欠落させるのではなく、HTML 上に置換メッセージを出すことで、利用者が何が起きたか理解できる。

## 決定

画像以外の添付ファイルも、可能な限り保存対象に含める。

添付ファイルにはサイズ上限を設け、`--max-attachment-size <size>` option で指定できるようにする。default は `10MB` とする。

サイズ上限を超える添付ファイルは download せず、HTML 上では元の添付表示を次のようなメッセージに置き換える。

```text
サイズオーバーのため保存されませんでした。
```

置換表示には、可能であればファイル名、Slack file ID、元の file size、設定された size limit を含める。

## 理由

Slack の投稿を archive する目的では、画像以外の添付ファイルも投稿内容の一部として扱う方が自然である。

一方で、添付ファイルには大きなファイルが含まれ得るため、無制限 download は CI やローカル実行で扱いにくい。明示的な size limit option を用意し、超過時に HTML 上で理由を表示すれば、保存範囲と欠落理由が明確になる。

## 影響

- `usage-flow.md` の保存対象 assets に、画像以外の添付ファイルを追加する。
- 出力構造には、画像以外の添付ファイルを置く `assets/attachments/` を含める。
- 実装では Slack file の size を確認し、上限以下の場合だけ download する。`--max-attachment-size` の default は `10MB` とする。
- 上限超過ファイルは download せず、HTML に置換メッセージを出す。
- `.cache/assets_manifest.json` には、保存した添付ファイルと、上限超過で保存しなかった添付ファイルの状態を記録する。
- CI では `--max-attachment-size` を指定することで artifact サイズを制御できる。

## 後から見直す条件

- 添付ファイルの種類ごとに別の上限が必要になる。
- 動画や音声など、大きくなりやすいファイルを初期対象から外す必要が出る。
- size limit の既定値を利用者層に合わせて調整する必要が出る。
