# 0048 ドキュメント文体(読者層別の文末・トーン・用語表記)

- 状態: decided
- 作成日: 2026-07-04
- 最終更新日: 2026-07-04
- 関連: `doc/guidelines/document-style-guidelines.md`, `doc/README.md`, `doc/help/README.md`

## 背景

ドキュメントの文体(文末・トーン)を定めたガイドラインが存在せず、repo root `README.md` がですます調、`doc/help/` が常体と、同じ利用者向け文書の中で語調が割れていた(#49 の quickstart 追加時に顕在化)。主な書き手が AI agent であるため、書き手ごとの揺れを防ぐには明文化された基準が必要になった。README 再構成(#123)で利用者向け層と開発者向け層を分ける前提とも関わるため、このタイミングで確定した。

## 候補

- 文末(利用者向け): (A) ですます調に統一。(B) 常体に統一。(C) README はですます・help は常体の現状分担を明文化して維持。
- 文末(開発者・AI agent 向け): (A) 常体に統一。(B) ですます調に統一。
- トーン: (A) 簡潔・中立。(B) ややフレンドリー(軽い呼びかけ・達成感の演出を許容)。(C) 規定しない。
- 適用範囲: 文末・トーンのみ / 用語表記・内容分担の要点も含める / 記法(見出し・表・スペース)まで含める。
- 既存文書への適用: 一括修正 Issue / 編集時に順次適用 / quickstart のみ即時修正。

## 検討内容

- 利用者向けのですます調は README の現状と一致し、初見の利用者への説明として自然。常体統一は help との差分は小さいが README の全面書き換えが必要で、利用者向けの印象も硬くなる。現状分担の明文化は「同じ読者層で語調が割れる」問題を解消しない。
- 開発者・AI agent 向けは既存文書がほぼ常体で、仕様・ルールの断定的な記述に向く。ですます化は書き換え量が大きく利点がない。
- トーンはドキュメントの魅力付けを構成(所要時間、期待出力例、プレビュー画像)で行う方針(#49 / #123)と合わせ、文章は簡潔・中立とした。
- 用語表記(技術用語は英語のまま)と読者層別の内容分担の要点は、現状慣習の明文化としてガイドラインに含めた。記法の統一はスコープ外とした。
- 既存文書への適用は、レビューしやすさを優先して一括修正を別 Issue(#126)に分離した。

## 決定

- 利用者向け(repo root `README.md`、`doc/help/` 配下。`doc/help/README.md` を除く): ですます調。
- 開発者・AI agent 向け(`doc/design/`、`doc/guidelines/`、`AGENTS.md`、`progress.md`、`working-branch-notes/`、各ディレクトリ `README.md`): 常体。
- トーン: 読者層によらず簡潔・中立。呼びかけ・励まし・絵文字は使わない。
- 技術用語は英語表記のまま使う。
- 正本は `doc/guidelines/document-style-guidelines.md` とし、rule 入口(Cursor / Claude Code)と `AGENTS.md` リンクを整備する。

## 理由

- 主な書き手が AI agent であり、セッションをまたいだ文体の一貫性は明文化されたルールでしか担保できない。
- 利用者向けと開発者向けで読者と目的が異なるため、層別の文体が最も低コストで自然な統一になる。現状の README(ですます)と開発文書(常体)の大勢を活かし、書き換え対象を `doc/help/` に最小化できる。

## 影響

- 新規・編集する日本語ドキュメントはこのガイドラインに従う。
- 既存の `doc/help/`(slack-app-setup / token-injection)と README の混在箇所は #126 で一括修正する。#49 で追加する quickstart は merge 前に PR #124 内で本ガイドラインへ合わせる。
- `doc/help/README.md` の「文体」節は内容方針の定義として「内容の方針」へ改名し、語調は本ガイドラインを参照する。
- README 再構成(#123)と制限事項・FAQ(#52)は本ガイドラインに従って書く。

## 後から見直す条件

- 英語版ドキュメントを提供することになり、多言語での文体方針が必要になった場合。
- 記法(見出し・表・スペース)の揺れが実際にレビューコストになった場合(スコープ外とした記法統一を追加検討する)。
