# 0001 試作プロジェクトとの関係

- 状態: decided
- 作成日: 2026-06-02
- 最終更新日: 2026-06-02
- 関連: `doc/design/usage-flow.md`, `progress.md`

## 背景

Slack の書き込みを閲覧しやすい HTML 形式で保存する目的に近い試作プロジェクトとして、[kiyohara/slack_posts_dumper](https://github.com/kiyohara/slack_posts_dumper) が存在する。

本リポジトリの設計作業では、この試作プロジェクトから知見を得られる可能性がある。一方で、試作時点の判断が本リポジトリの正式な方針として暗黙に採用されると、検討経緯が不明確になり、後続の AI agent や人間が判断理由を辿れなくなる。

## 候補

- 試作プロジェクトを本リポジトリの前提として扱い、実装や方針を可能な限り踏襲する。
- 試作プロジェクトを参考資料として扱うが、本リポジトリの方針は個別に議論して決める。
- 試作プロジェクトを参照しない。

## 検討内容

試作プロジェクトには、Slack API の利用、HTML 出力、絵文字やアセット処理など、本リポジトリの検討に役立つ情報が含まれる可能性がある。

ただし、試作プロジェクトは本リポジトリとは別の文脈で作られており、そこで選ばれた技術スタック、権限、出力仕様、運用方法がそのまま現在のプロダクト要件に適するとは限らない。参照する場合も、各方針は本リポジトリの利用手順、保守性、セキュリティ、AI agent 共同作業の前提に照らして再検討する必要がある。

## 決定

[kiyohara/slack_posts_dumper](https://github.com/kiyohara/slack_posts_dumper) は参考資料として扱う。

ただし、試作プロジェクトで採用された方針を本リポジトリで暗黙に採用しない。Slack API 権限、保存形式、HTML 表示、アセット管理、実装アーキテクチャなどの方針は、本リポジトリの decision log または設計ドキュメント上で個別に議論して決める。

## 理由

試作プロジェクトを完全に無視すると既存知見を活かせず、同じ調査や実装検討を繰り返す可能性がある。

一方で、試作プロジェクトを前提化すると、本リポジトリ固有の要件や設計判断が見えにくくなる。参考資料として位置づけを限定することで、知見を活用しつつ、正式な方針決定の経緯を本リポジトリ内に残せる。

## 影響

- 設計検討時に試作プロジェクトを参照してよい。
- 参照した内容を正式方針にする場合は、個別に decision log または該当設計ドキュメントへ記録する。
- 個人環境に依存する作業ディレクトリの相対パスは記録しない。ポインタが必要な場合は GitHub リポジトリ URL を使う。

## 後から見直す条件

- 試作プロジェクトから本リポジトリへ大部分の実装を移植する方針になった場合。
- 試作プロジェクトを参照し続けることが、設計判断の混乱や情報統制上のリスクにつながった場合。
- 本リポジトリ側の仕様が固まり、試作プロジェクトを参照する必要がなくなった場合。
