# ドキュメント文体ガイドライン

この文書は、このリポジトリの日本語ドキュメントを作成・編集するときの文体(文末・トーン・用語表記)の共通正本である。主な書き手は AI agent だが、人間も同じルールに従う。

どこに何を置くかの配置ルールは `doc/README.md` と各ディレクトリの `README.md` を正本とする。本ガイドラインは「置き場所が決まった文書をどう書くか」だけを扱う。

## 読者層と文体の対応

| 読者層 | 対象 | 文末 | トーン |
|---|---|---|---|
| 利用者向け | repo root `README.md`、`doc/help/` 配下(`doc/help/README.md` を除く) | ですます調 | 簡潔・中立 |
| 開発者・AI agent 向け | `doc/design/`(decision log 含む)、`doc/guidelines/`、`AGENTS.md`、`progress.md`、`working-branch-notes/`、各ディレクトリの `README.md` | 常体(である調) | 簡潔・中立 |

ディレクトリ配置を説明する `README.md`(`doc/README.md`、`doc/help/README.md` など)は、利用者ではなくメンテナと AI agent が読むため、開発者向けとして扱う。

## 文末

- 利用者向けはですます調で統一する。手順の指示は「〜します」「〜してください」とする。
- 開発者・AI agent 向けは常体で統一する。仕様・ルールは「〜する」「〜とする」と断定で書く。
- 同一文書内で文体を混在させない。
- 表のセル、チェックリストや箇条書きの短い語句、見出しは体言止めを使ってよい。項目が文になる場合は文書の文体に合わせる。
- コマンド出力例、外部サービスの UI 表記、引用は原文のまま書く。

## トーン

- 読者層によらず簡潔・中立とする。呼びかけ、励まし、感嘆、絵文字は使わない。
- 利用者向けでも装飾的な文で魅力付けしない。読みやすさは構成(所要時間の目安、期待出力例、プレビュー画像など)で確保する。
- 事実と手順を書き、推測や設計上の迷いを利用者向け文書に持ち込まない。

## 用語表記

- Slack / CLI の技術用語(workspace、channel、token、scope、export、install、option、cache など)は英語表記のまま使い、カタカナ・日本語訳への言い換えをしない。
- 外部サービスの画面ラベルは実際の UI 表記に合わせる(例: `OAuth & Permissions`)。
- 同じ概念に複数の表記を使わない。迷ったら既存文書の表記に合わせる。

## 読者層ごとの内容分担(要点)

配置の正本は `doc/README.md` と各ディレクトリの `README.md` だが、文体判断に直結する要点を再掲する。

- 利用者向け文書には、開発視点の情報(設計経緯、開発環境、実装詳細)を書かない。
- 利用者向け文書から decision log へ直接リンクしない(`doc/guidelines/decision-log-guidelines.md`)。
- 利用者向け help の内容方針(そのまま実行できる手順として書く等)は `doc/help/README.md` の「内容の方針」節を正とする。
- 開発者向け情報への入口は repo root `README.md` の末尾に最小限のリンクとして置き、利用者向け本文に混ぜない。

## 適用

- 新規作成・編集する文書から適用する。
- 既存文書の文体だけを直す変更は、専用の Issue / PR として計画的に行い、無関係な PR に混ぜない。
