# Decision Log 記録ルール

この文書は、AI agent が設計判断や方針決定の検討経緯を decision log として記録するときの共通正本である。

## 目的

Decision log は、決定済みの方針だけでなく、どのような経緯と検討の結果その方針に至ったのかを後から辿れるようにするための記録である。

主な読者は AI agent だが、人間も同じ正本を読む。

## 正本と参照の関係

- 仕様の正本は `doc/design/` 直下の各 spec 文書(例: `usage-flow.md` / `output-format.md` / `html-rendering.md` / `cache.md`)である。
- decision log は、その仕様がどう確定したかを辿るための参考ログであり、仕様の正本ではない。`index.md` も参考ログの入口であって正本ではない。
- 参照の向きは、decision log → spec を冒頭の `関連` で示し、spec → decision log を各 spec 文書から「決定経緯」として参照する。
- decision log や `index.md` を「仕様の正本」として扱ったり、そう記述したりしない。
- 文書再編で内容が spec 間を移動したら、移動元を指していた `関連` を移動先 spec へ更新する。本文(背景・検討・決定・影響)は当時の記録なので書き換えず、旧 spec への言及が残ってよい。

## 対象読者と利用者向け文書からの参照

- decision log は開発時に参照する内部ドキュメントである。主な読者は AI agent と開発者であり、一般利用者が読む前提ではない。
- 利用者向けドキュメント(repo root の `README.md` と `doc/help/` 配下)からは、decision log へ直接リンクしない。利用者に必要な情報は利用者向け文書に本文として書くか、利用者向けの spec / help へリンクする。
- `doc/design/` 配下の spec 文書からの「決定経緯」としての decision log 参照は、開発者向けの内部参照として許容する(「正本と参照の関係」を参照)。
- 経緯は `doc/design/decision-log/0039-decision-log-audience.md`。

## 配置

```text
doc/design/decision-log/
├── index.md
├── _template.md
└── <連番>-<短い英語slug>.md
```

- `index.md`: AI agent と人間が最初に読む入口。現在有効な主要方針、未決事項、参照先だけを簡潔に置く。
- `_template.md`: 個別ログを作るときのひな形。
- `<連番>-<短い英語slug>.md`: 1 テーマ 1 ファイルの詳細ログ。

## 記録が必要な場面

- 実装アーキテクチャ、Slack API の使い方、保存形式、出力構造、設定方式などの方針を決めるとき。
- 複数案を比較し、採用案と却下案が生じたとき。
- 以前の方針を変更、撤回、上書きするとき。
- 後続の AI agent が判断理由を知らないと同じ議論を繰り返しそうなとき。

ブランチ内の小さな作業メモ、TODO、一時的な試行錯誤は `working-branch-notes/` に置く。タスクの実行指示は GitHub Issue、横断的な状態・依存と Issue / PR 参照は `progress.md` に置き、decision log に作業ログを混ぜない。

## AI agent の記録手順

1. まず `doc/design/decision-log/index.md` を読む。
2. 既存ログに同じ主題がないか確認する。
3. 新規主題なら `_template.md` を元に `<連番>-<短い英語slug>.md` を作る。
4. 既存主題の更新なら該当ログに追記する。決定が変わる場合は古いログを消さず、状態を `superseded` にして新しいログへリンクする。
5. `index.md` の「現在有効な主要方針」または「未決事項」を更新する。
6. 関連する `doc/design/usage-flow.md` や `progress.md` に影響がある場合は、必要な最小限の参照を追加する。

## ファイル名

ファイル名は次を基本とする。

```text
0001-output-scope.md
0002-slack-api-permissions.md
0003-html-asset-storage.md
```

- 連番は 4 桁にする。
- slug は短い英語の kebab-case にする。
- 連番は作成順を表し、後から意味順に並べ替えない。

## 状態

個別ログの `状態` は以下を使う。

- `proposed`: 提案中。まだ合意または採用していない。
- `decided`: 採用済み。現在有効な方針。
- `superseded`: 別のログで上書き済み。
- `rejected`: 検討したが採用しないことにした。

## index の書き方

`index.md` には詳細な議論を書かない。

- 現在有効な主要方針には、`decided` のうち後続判断に効くものを載せる。
- 未決事項には、`proposed` または検討予定の主題を載せる。
- 詳細欄には個別ログへの相対リンクを書く。
- 古い方針が `superseded` になった場合、現在有効な主要方針からは外し、必要なら個別ログ同士でリンクする。

## 個別ログの書き方

個別ログは `_template.md` に従う。

- 背景: なぜ検討が必要になったか。
- 候補: 検討した選択肢。
- 検討内容: 利点、欠点、制約、判断材料。
- 決定: 採用した方針。未決なら現時点の仮説を書く。
- 理由: その判断に至った理由。
- 影響: 利用手順、実装、テスト、運用、ドキュメントへの影響。
- 後から見直す条件: 再検討すべき条件。

## 禁止事項

- `index.md` に長い議論や詳細ログ本文を詰め込む。
- 古い判断を消して履歴を失わせる。
- AI agent 固有の会話ログをそのまま貼り付ける。
- Slack token、個人情報、顧客固有情報、出力 HTML に含まれる機密情報を書く。
- 進捗管理と decision log を混ぜる。
