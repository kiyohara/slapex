# Decision Log 記録ルール

この文書は、AI agent が設計判断や方針決定の検討経緯を decision log として記録するときの共通正本である。

## 目的

Decision log は、決定済みの方針だけでなく、どのような経緯と検討の結果その方針に至ったのかを後から辿れるようにするための記録である。

主な読者は AI agent だが、人間も同じ正本を読む。

## 配置

```text
doc/product/decision-log/
├── index.md
├── _template.md
└── <連番>-<短い英語slug>.md
```

- `index.md`: AI agent と人間が最初に読む入口。現在有効な主要方針、未決事項、参照先だけを簡潔に置く。
- `_template.md`: 個別ログを作るときのひな形。
- `<連番>-<短い英語slug>.md`: 1 テーマ 1 ファイルの詳細ログ。

## 記録が必要な場面

- 実装アーキテクチャ、Slack API の使い方、保存形式、出力構造、設定方式などの方針を決めるとき。
- 複数案を比較し、採用案と却下案が生じたとき。
- 以前の方針を変更、撤回、上書きするとき。
- 後続の AI agent が判断理由を知らないと同じ議論を繰り返しそうなとき。

小さな作業メモ、単純な TODO、実装中の一時的な試行錯誤は `doc/product/progress.md` に寄せ、decision log を肥大化させない。

## AI agent の記録手順

1. まず `doc/product/decision-log/index.md` を読む。
2. 既存ログに同じ主題がないか確認する。
3. 新規主題なら `_template.md` を元に `<連番>-<短い英語slug>.md` を作る。
4. 既存主題の更新なら該当ログに追記する。決定が変わる場合は古いログを消さず、状態を `superseded` にして新しいログへリンクする。
5. `index.md` の「現在有効な主要方針」または「未決事項」を更新する。
6. 関連する `doc/product/usage-flow.md` や `doc/product/progress.md` に影響がある場合は、必要な最小限の参照を追加する。

## ファイル名

ファイル名は次を基本とする。

```text
0001-output-scope.md
0002-slack-api-permissions.md
0003-html-asset-storage.md
```

- 連番は 4 桁にする。
- slug は短い英語の kebab-case にする。
- 連番は作成順を表し、後から意味順に並べ替えない。

## 状態

個別ログの `状態` は以下を使う。

- `proposed`: 提案中。まだ合意または採用していない。
- `decided`: 採用済み。現在有効な方針。
- `superseded`: 別のログで上書き済み。
- `rejected`: 検討したが採用しないことにした。

## index の書き方

`index.md` には詳細な議論を書かない。

- 現在有効な主要方針には、`decided` のうち後続判断に効くものを載せる。
- 未決事項には、`proposed` または検討予定の主題を載せる。
- 詳細欄には個別ログへの相対リンクを書く。
- 古い方針が `superseded` になった場合、現在有効な主要方針からは外し、必要なら個別ログ同士でリンクする。

## 個別ログの書き方

個別ログは `_template.md` に従う。

- 背景: なぜ検討が必要になったか。
- 候補: 検討した選択肢。
- 検討内容: 利点、欠点、制約、判断材料。
- 決定: 採用した方針。未決なら現時点の仮説を書く。
- 理由: その判断に至った理由。
- 影響: 利用手順、実装、テスト、運用、ドキュメントへの影響。
- 後から見直す条件: 再検討すべき条件。

## 禁止事項

- `index.md` に長い議論や詳細ログ本文を詰め込む。
- 古い判断を消して履歴を失わせる。
- AI agent 固有の会話ログをそのまま貼り付ける。
- Slack token、個人情報、顧客固有情報、出力 HTML に含まれる機密情報を書く。
- 進捗管理と decision log を混ぜる。
