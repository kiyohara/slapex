## 所見 1: code block 内の URL が表示されない

- 事象: `#meetup165` の export で、code block 内にあった URL が HTML 上で表示されない。
- 原因(確認済み): Slack は code block / inline code の中でも URL を `<URL>` 構文(auto-link)で格納する。PoC の mrkdwn 変換器は「Slack text は `&` `<` `>` をエンティティ化済みであり、生の `<` は構文のみ」という前提で code 内容を未処理のまま `<pre><code>` に出力するため、生成 HTML に生の `<URL>` がそのまま残り、browser が未知の HTML タグとして解釈して非表示になる。生成 HTML 内に生の `<URL>` が残っていることを実出力で確認した。
- 影響: 表示欠落に加え、code 内の生 `<` `>` を素通しするエスケープ防御の穴でもある(構文の文法上、任意 HTML の注入は困難だが、防御的に塞ぐべき)。
- 修正方針(実装フェーズ): code span / code block の内容に対しても `<URL>` / `<URL|label>` 構文を表示テキストへ展開し、そのうえで残る生の `<` `>` を HTML エスケープして出力する。利用者が入力した `<` は Slack 側で `&lt;` 化されているため、二重エスケープは起きない。
- 記録先: decision log index 未決事項「code block 内の URL 構文の表示」(関連 0026)。

## 所見 2: タイムゾーンが JST にならない

- 事象: ディレクトリ名(実行時刻由来)と本文の時刻表示が UTC になっている(期待は JST)。
- 原因(確認済み): 実装は仕様 0028「実行環境の local timezone で表示」のとおり動作しているが、Docker 経由で実行すると「実行環境」= コンテナとなり、コンテナのデフォルト timezone が UTC のため、表示・ディレクトリ名とも UTC になる。golang image に tzdata は含まれており、`docker compose run --rm -e TZ=Asia/Tokyo dev ...` のように `TZ` を渡せば JST 表示になることを確認した。
- 補足: 単一バイナリを host で直接実行する本来の配布形態では host の local timezone(JST)が自然に使われ、仕様どおりの結果になる。`.cache/` 内の時刻が ISO 8601 UTC なのは仕様(`cache.md`)。
- 対応候補(実装フェーズで判断): (a) dev / E2E 手順で host の `TZ` をコンテナへ forward する(compose または実行コマンド)。(b) `--tz` などの明示指定 option を導入する(0028 の「後から見直す条件」に該当する需要が出たと言える)。
- 記録先: decision log index 未決事項「コンテナ実行時のタイムゾーン」(関連 0028)。
